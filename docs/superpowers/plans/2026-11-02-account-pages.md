# 구글 계정 안내 페이지 구현 계획

목표: 기존 저장소에 무료 홈페이지와 개인정보처리방침, 이용 안내를 게시하고 구글 앱 등록에 사용할 주소를 준비한다.

구성: `docs/index.html`, `docs/privacy.html`, `docs/terms.html`은 공통 `docs/site.css`를 사용한다. `docs/.nojekyll`로 별도 문서 변환 없이 제공한다.

제약: 실행 코드와 설치 파일은 그대로 유지한다. 개인 설정이나 계정 자료를 읽어 공개 콘텐츠로 옮기지 않는다. 웹사이트에 별도 로그인이나 분석 기능을 추가하지 않는다.

## 1. 안내 문서 작성

- [x] 실제 실행 코드에서 요청 정보와 저장 방식을 확인한다.
- [x] 세 문서, 공통 스타일, 정적 게시 표시 파일을 작성한다.
- [x] `docs/GOOGLE_CONNECTION.ko.md`에 테스트 앱의 7일 만료와 운영 전환 조건을 추가한다.
- [x] 두 안내서에 홈페이지 링크를 추가하고 `public-files.json`을 갱신한다.

## 2. 확인과 기본 브랜치 반영

- [ ] 임시 로컬 서버에서 문서 세 개의 내부 링크와 모바일 너비를 확인한다.
- [ ] `node --test tests/*.test.mjs`로 기존 자동 검사를 실행한다.
- [ ] 소스 검토 후 작업 브랜치를 올리고 원격 자동 검사 성공을 확인한다.
- [ ] 기본 브랜치에 충돌 없이 반영한다.

## 3. 게시와 구글 등록

- [ ] 깃허브 페이지 게시 원본을 기본 브랜치의 `/docs`로 설정한다.
- [ ] 공개 홈페이지, 개인정보처리방침, 이용 안내가 정상 응답하는지 확인한다.
- [ ] 구글 앱의 승인된 도메인과 세 문서 주소를 등록한다.
- [ ] 소유 확인과 운영 전환에서 필요한 승인을 실제 화면 기준으로 요청한다.
- [ ] 운영 전환이 완료된 경우 계정을 다시 연결하고 실제 일정 조회를 확인한다.
