# 달력 호출 기능 구현 계획

승인된 설계: `docs/superpowers/specs/2026-10-08-calendar-peek-design.md`.

목표: 버튼 없이 화면 모서리로 달력을 호출하고 다른 기기에서도 같은 설치 파일로 업데이트한다.

구조: `@Resources/CalendarPeek.cs`에 상태 전이·설정·창 제어를 모은다. `@Resources/CalendarPeek.ps1`은 이를 로드하고 실행한다. `CalendarPeek.ini`는 기본 사용자 설정이다. `GoogleCalendar.ini`는 숨김 프로세스를 시작하며 갱신·언로드 시 RunCommand가 종료한다.

- [x] `tests/calendar-peek.test.ps1`에 실제 C#(씨샵) 상태 전이, 설정과 좌표 계산 테스트를 먼저 작성하고 실행하여 기능 부재로 실패하는지 확인한다.
- [x] C# 상태 전이와 Windows(윈도우) 어댑터, PowerShell 실행기를 구현하고 테스트를 통과시킨다. 대기 400밀리초, 닫힘 600밀리초, 드래그·전체 화면 차단, 중복 프로세스 방지, 원래 위치 복원을 확인한다.
- [x] 스킨 시작 동작·기본 설정·배포 목록·설정 보존 목록을 연결하고 한국어 및 영문 설명을 갱신한다.
- [x] 기존 패키징 검사에 1.2.0을 연결하고 설치 파일을 생성한 뒤 전체 테스트를 실행한다.
- [x] 코드 검토와 로컬 설치·실행 검증을 마치고, 개인정보 없는 변경 및 설치 파일을 깃허브 배포용으로 준비한다.

실행 명령: `node --test tests/*.test.mjs` 및 `powershell -NoProfile -File tests/calendar-peek.test.ps1`. 네트워크 설치 없이 기존과 동일한 ical.js(일정 파서) 2.2.1을 사용한다.

실제 화면 검증: 원래 보조 모니터의 바탕화면 위치에서 주 모니터의 호출 위치로 이동, 대기 시간, 다른 창 위 표시, 내부 유지, 자동 닫힘, 원래 위치 복원, 제어기 한 개 실행을 확인했다. 검증용 임시 설정은 원본 바이트로 복원했다. 화면 배율 차이를 피하기 위해 물리 좌표로 직접 창을 이동하며 레인미터가 받는 창 이동 이벤트로 내부 위치를 갱신한다.

배포 검증: 공식 설치기와 같은 16바이트 패키지 꼬리말을 추가했다. 호출 설정은 설치기가 보존하는 `[Variables]`(변수 구역)을 사용하며 이전 개발 설정 구역도 읽을 수 있다. 현재 기기의 설정은 값을 유지한 채 구역을 전환했다. 전체 검사 97개를 통과했다.
