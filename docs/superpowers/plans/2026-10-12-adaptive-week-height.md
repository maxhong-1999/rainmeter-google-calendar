# 적응형 주 높이 구현 계획

목표: 일정 내용과 커서 위치에 맞춰 주별 확장을 줄인다.

구조: `calendar-week-focus.mjs`(주 선택 제어)의 `weekTracks(week, contentHeight, pointerY)`(주 높이 계산)에 높이 제한과 커서 유지 계산을 모은다. 제어기는 기존 상세 목록의 자식 높이를 측정하고 마우스 위치를 전달한다. 화면 스타일과 일정 파서는 변경하지 않는다.

- [x] `tests/calendar-week-focus.test.mjs`(주 선택 검사)에 빈 내용 52픽셀, 내용 44픽셀일 때 74픽셀, 상한 108픽셀과 전체 높이 317픽셀을 검사하고 실패를 확인한다. 서로 다른 기존 주·새 주·포인터 위치에서 선택 영역이 커서를 포함하는지 검사한다.
- [x] `weekTracks`(주 높이 계산)를 수정한다. 내용과 여백 합을 제한하고, 선택 주의 위·아래 경계가 포인터를 포함하는 최소 높이를 계산한다. 나머지는 `(312 - selectedHeight) / 5`(남은 높이의 균등 분배)로 만든다.
- [x] 제어기에서 날짜별 상세 자식의 높이·위아래 여백을 합산하고 최댓값을 계산한다. 실제 마우스 위치를 기록하고 키보드 선택·이탈·초기화 시 구분한다.
- [x] 예시 일정 브라우저에서 빈 주·단일 일정·많은 일정의 높이 차이, 정지한 커서 유지, 일정 감소 시 높이 축소와 기존 기능을 검사한다. 코드 검토 후 현재 화면에 적용해 수치로 확인한다.
- [x] 안내와 배포 목록을 갱신하고 1.3.1 설치 파일을 만든다. `node --test tests/*.test.mjs`(전체 검사)를 통과한 뒤 깃허브 자동 검사와 배포를 준비한다.

- [x] 실제 레인미터의 모듈 캐시 재사용을 확인하고 진입 스크립트·주 선택 모듈 주소에 같은 배포 버전을 붙인다. 캐시 버전 검사와 실제 화면 108픽셀 제한 검사를 통과했다.
