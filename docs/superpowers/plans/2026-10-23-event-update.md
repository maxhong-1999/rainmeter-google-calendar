# 기존 일정 수정 구현 계획

목표: 기존 추가·삭제 화면에 제목·날짜·시간 수정을 연결하고 계정 연결을 준비한다.

구조: 기존 편집 화면과 실행기를 재사용한다. 새 외부 의존성을 추가하지 않는다. 실제 계정 자료는 검사와 배포에서 제외한다.

- [x] tests/calendar-editor.test.mjs(화면 입력 검사)에 기존 일정의 날짜·시간·종일 마지막 날짜 왕복 검사를 추가하고 실패를 확인한다. eventFormValues(event)(폼 입력값 변환)을 구현한다.
- [x] tests/calendar-bridge.test.ps1(구글 실행기 검사)에 선택 회차 수정, 변경값·달력 불일치와 읽기 전용 보호 검사를 먼저 추가한다. CalendarBridge.ps1(연동 실행기)에 update(수정) 작업을 구현해 통과시킨다.
- [x] calendar-editor.mjs(편집 화면)와 calendar.html(달력 화면)의 기존 폼을 재사용한다. 수정 대상 식별값을 고정하고 성공 시 이전 날짜의 캐시를 제거한다. 예시 브라우저에서 수정·종일 전환·실패 후 입력 유지·조회 실패를 확인한다.
- [x] 문서·공개 목록과 1.5.0 설치 파일을 갱신한다. 전체 검사와 기존 확장 동작을 확인하고 검토 후 현재 달력에 적용한다.
- [ ] 저장소·배포에 반영한다. 클라우드 생성 승인과 계정 연결이 완료되어야 실제 구글 조회 여부를 확인할 수 있음을 명시한다.
